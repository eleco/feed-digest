# Privacy policy — developer preview

Effective 4 October 2026. The extension stores data locally by default. There is no telemetry, advertising or analytics. An optional online reader uses Basic Auth and a private Vercel Blob file. Exporting for the online reader creates a file containing saved post text, authors, dates, links, pins and AI scores/labels. Uploading that file to your reader shares those fields with your configured hosting/storage provider. API keys, settings, feedback and AI request logs are excluded. Each upload replaces the online copy. No automatic sync occurs. Hosting providers also process ordinary request metadata under their own policies.

The extension reads rendered post cards and author hover cards only in an extension-owned `https://x.com/home` tab in your normal signed-in session. It does not read cookies, credentials, DMs, bookmarks or other browsing. It stores canonical post links/IDs, author names/handles, rendered text/quoted text, available timestamps, feed/run observations, visible reply, like, view and author follower counts when available, rendered outgoing links with post/quote provenance, and markers. Comment threads and linked destinations are not opened automatically. A visible account handle is retained to detect account changes. Scans may briefly open author hover cards to read follower counts. X itself receives normal page loading, scrolling and hover-card traffic.

Posts, runs, feedback, digests, usage counters and caches live in extension-origin IndexedDB. Preferences and scheduling notices live in Chrome local storage. Keys default to session-only storage restricted to trusted extension contexts. Remember key is optional, persistent and not an encrypted vault. Provider keys do not go to the content script, page DOM outside the masked user-entry field, model prompts, logs or exports.

Basic mode makes no model requests. Scanning only collects posts. Clicking Analyse visible posts sends only pending posts matching the current digest view for analysis using the configured provider. The separate Analyse all saved posts action includes pending posts outside the current view and requires confirmation; checking the connection does not start analysis. Provider-origin access must be granted before requests can be made. It sends bounded collected post text, quoted text, excerpt indicators, opaque candidate IDs. Structured author names/handles, source URLs, engagement and previous digest text are omitted. Post text itself may identify people or contain personal information. OpenRouter forwards requests to model providers. Optional online processing is not local-only and retention is not guaranteed to be zero. AI sector and tone labels are stored with digest results. Read [Anthropic privacy](https://www.anthropic.com/legal/privacy), [OpenRouter privacy](https://openrouter.ai/privacy) or [OpenAI API data use](https://developers.openai.com/api/docs/guides/your-data). Connection checks send the user key in an HTTPS authentication header (Authorization or x-api-key), never a prompt.

The extension prunes unpinned posts older than 30 days and excess unpinned posts beyond 5,000, removing associated feedback/references. Pinned records remain until unpinned or explicitly deleted. Older runs/digests and model caches expire. Exports occur only after your action and include potentially sensitive text. Manual Copy AI prompt puts a bounded selection in your clipboard; pasting it into another service shares it under that service's policy.

Delete all data stops the current run, removes all IndexedDB stores, local/session settings and keys, scheduling alarms and optional provider permissions. It cannot retract data already sent to a provider, delete exports you saved elsewhere, or remove a collection uploaded to the online reader. Delete the reader/saved-posts.json.gz object in your private Blob store to remove the online collection. Uninstalling removes extension-managed browser data under Chrome's behavior.

No privacy contact has been designated for a public release. A maintainer must add an appropriate project contact before publication; do not send credentials or private feed exports in public issues.

AI activity logs are stored locally with scan history for 30 days. They include bounded post/quote excerpts, classifications, model/provider, request timing/status, token counts and available cost estimates. Logs and their optional JSON exports omit API credentials and raw provider responses. Delete all data removes these logs.

Jev theme matching is a separate opt-in integration. Clicking Analyse themes with Jev sends bounded collected post and quoted text to api.typesafe.ai using your own key. Connection checks list models only. Theme probabilities, model/version and the bounded source text are cached in the existing local IndexedDB cache for up to 30 days and deleted by Delete all data. Credentials use trusted extension session storage by default, with an explicit persistent-storage option. No key goes to the website; post content reaches the optional online reader only when you upload an exported reader file. See [TypeSafe data handling](https://docs.typesafe.ai/legal).
